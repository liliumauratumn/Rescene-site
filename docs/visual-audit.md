# RESCENE FANSITE 視覚監査

## 目的

この監査は、機能修正やリファクタリングによってClaude Design由来の差異が失われていないことを確認するために行う。新しい不規則性を探したり、ノイズ量を増やしたりする工程ではない。

保護対象は`docs/rescene-required-noise-profile.md`を正本とする。

## 判断順序

各画面では、必ず次の順番で判断する。

1. 読めるか。
2. 操作できるか。
3. WCAG 2.2 AAを壊していないか。
4. 差異が機能を害していないか。
5. リファクタリングによって既存の差異が消えていないか。
6. 不規則性を新しいテンプレートとして量産していないか。

上位項目と下位項目が衝突した場合は、上位項目を優先する。元カンプとの差だけを理由にアクセシビリティ修正を戻さない。

## 必須幅

最低限、次のviewportで変更前後を比較する。

| Width | 主な確認 |
| ---: | --- |
| `1440px` | デスクトップの全体構図、Heroヒット領域、非等分grid、表形式、hover/focus |
| `390px` | iPhone 12 mini相当、Hero表示、Member stagger、情報順、Mobile Menu、focus |
| `320px` | 最小幅reflow、文字切れ、横スクロール、タッチ領域、crop |

必要に応じて`768px`と`1024px`も追加し、デスクトップとモバイルの境界で表示が途切れないことを確認する。

## 比較方法

1. 変更前の同一ルート・同一viewport・同一状態をスクリーンショットに残す。
2. 変更後も同じスクロール位置、hover、focus、メニュー状態で撮影する。
3. 全ページ画像だけでなく、保護対象の近接画像も比較する。
4. 画像差分だけで判断せず、実ブラウザでTab、Shift+Tab、Enter、Space、Escape、タッチ相当操作を確認する。
5. computed styleで保護値を確認し、DOM順・アクセシビリティツリー・コンソールエラーも確認する。
6. 差異を変更した場合は、変更対象、変更前後の値、比較した幅、採用理由を作業記録へ残す。

## 画面別チェック

### Hero — `/`

#### 1440px

- `hero.png`全体が`2880 × 1800`の比率で表示され、上部文字、5人の個別crop、人物間の黒い余白、下部brushと罫線が欠けていない。
- 人物順が`MAY → LIV → ZENA → MINAMI → WONI`である。
- 5つのヒット領域が画像内の人物位置と対応し、小数percentageと不均一な間隔が維持されている。
- hoverとfocusで名前が領域下部に表示され、focus ringが明暗背景の両方で見える。
- ヒット領域とその下の5等分名前導線を混同していない。

#### 390px / 320px

- Hero画像そのものが消えていない。
- デスクトップ用ヒット領域だけが非表示になり、メンバーへの名前導線は残る。
- 画像がviewport外へ横にはみ出さず、重要な構図が意図せずcropされていない。

### Member一覧とホームMembers — `/members/`、`/`

- ホームの順序が`MAY → LIV → ZENA → MINAMI → WONI`である。
- 1440pxでMAY/WONIは基準位置、LIV/MINAMIは`42px`下、ZENAは`16px`下にある。
- 390pxと320pxでデスクトップmarginが解除され、偶数カードだけが`24px`下がる。
- stagger後の説明文がカードと衝突せず、`54px`の受け余白が残る。
- 画像が粗く見える場合も、外部画像の取得や人工補間を行わない。権利・画質問題は人間確認へ戻す。
- `/members/`の情報行を、ホームカードと同じ見た目へ共通化していない。

### Member detail — `/members/minami/`を代表として5人を確認

- 1440pxでportraitが左に置かれ、`318px / 残り`のgrid、左18px margin、`50% 12%`の非中央cropが維持される。
- 写真、breadcrumbs、名前、プロフィール表、操作導線の順序と重なりが崩れていない。
- 390pxと320pxではportraitが本文の前へ移り、`contain / center`で全体を表示する。
- 5人すべてで頭部・顔・主要な構図が欠けず、素材内部の個体差を一括cropで消していない。
- 低解像度素材を無理に拡大して画質問題を隠していない。必要なら既存の画像なし状態を使う。

### Discography — `/discography/`、`/discography/yoyo/`

- 1440pxで一覧の左右線、ヘッダー、各行の下線、5つの非等分列が残る。
- 暗色／白色の行が交互になり、両方の通常・hover・focus状態で文字が読める。
- 一覧がジャケット画像の均質カードグリッドへ変わっていない。
- 390pxと320pxでヘッダーが隠れ、各行が1列へreflowし、形態・タイトル曲・香りのラベルが読める。
- 作品詳細のTrack Listで`01`等の番号列が残り、デスクトップ`64px`、モバイル`44px`の存在感が維持される。

### Guide — `/guide/first-rescene/`、`/guide/japan-events/`

- 明るい背景上でセクション番号、見出し、本文、動画タイトル、公式導線が読める。
- GUIDE番号と動画番号は現在のWCAG対応色`#69655d`を維持し、元の低コントラスト色へ戻っていない。
- 1440pxの番号列と本文列、390px/320pxの再構成で、番号の存在感と本文の可読性が両立する。
- hoverとfocusが明るい背景でも見える。

### Japan Archive — `/japan/`

- 年見出し列と記録列、各記録の日付列と本文列が別の比率を保つ。
- 1px罫線によるタイムライン構造が、均質カード一覧へ置換されていない。
- フィルター、年、日付、活動種別、本文の情報順が390px/320pxでも理解できる。
- Sticky Header移動時に対象行やfocusが完全に隠れない。

### Mobile Menu — 全主要ルート

- 390pxと320pxで開閉でき、Escapeで閉じ、閉じた後にトリガーへfocusが戻る。
- TabとShift+Tabのfocus trapが機能する。
- 現在ページが色だけでなく`aria-current`でも分かる。
- focus ringが見え、48pxの主要操作領域を維持する。
- メニュー表示中に背景が意図せずスクロールせず、閉じた後にbody状態が戻る。

## 共通の失敗条件

- 横スクロール、文字切れ、操作不能、フォーカス消失がある。
- コントラスト、ARIA、タッチ領域、Reduced Motionをカンプ再現のために悪化させている。
- Hero人物座標、Member stagger、非等分grid、画像重心、Discography交互行、brush cropが理由なく共通値へ置換されている。
- `160ms ease`、角丸0、中央cropなど、既存の共通値を新規要素へ無検討でコピーしている。
- 不規則角丸、傾き、ランダムtransition、装飾motionを「必須ノイズ」として機械的に追加している。
- コードが整理された一方で、変更前後の視覚比較が残っていない。
